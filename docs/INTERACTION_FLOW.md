# Intuition Engine Agent 交互流程叙述

## 最终效果定位

Intuition Engine Agent 的最终效果不是把文档压缩成摘要，而是把一段文本、技术文档、PPT 或开源项目 introduction 转成一页可观看、可操作、可验证的 2D/3D 教学动画。用户看到的是一部 Interactive Knowledge Movie：知识点按镜头展开，核心对象可见，因果关系通过动画发生，参数变化会真实改变画面结果。

## 主流程

1. 用户输入资料

   用户粘贴文本或上传文档。后续输入类型包括 PDF、Markdown、HTML、网页 URL、PPT 和开源项目介绍。

2. Agent 解析文档

   后端将原始资料切分成结构化章节块，识别标题、段落、参数、表格和关键说明。

3. Agent 理解内容

   系统从文档中抽取核心对象、流程关系、状态变化、条件判断、异常处理和可互动参数。例如 ROS 文档中的 Publisher、Topic、Subscriber、Message，或小车避障文档中的小车、雷达、障碍物、安全距离。

4. 生成教学分镜

   Agent 将技术内容拆成多个教学镜头。每个镜头都说明画面对象、对象状态、动作、旁白重点和用户可交互点，避免只输出大段文字。

5. 匹配对象库和模板库

   对常见领域优先复用已有对象和交互模板。ROS 使用 Node、Topic、Message、源码片段、机器人状态等模板；机器人避障使用小车、雷达扇形、测距射线、障碍物、控制器和轨迹模板。

6. 生成受控动画 JSON spec

   Agent 不直接生成任意前端代码，而是输出受 schema 约束的动画 spec。spec 描述场景、对象、镜头、运动、点击行为、源码关联、图谱关系和参数控件。

7. 校验与质量检查

   后端检查 spec 是否符合 schema，是否只使用白名单对象和模板，并检查页面是否只是文字堆叠、关键对象是否可见、交互是否真实改变动画。

8. 前端渲染知识电影

   前端用 Canvas、SVG 或 Three.js 消费 JSON spec，生成可滚动推进、可播放暂停、可单步讲解的互动教学页面。

## 用户进入页面后的交互闭环

用户进入第一页后，先看到一个具象场景，而不是长篇说明。滚轮、时间轴或单步按钮推进镜头，核心对象按顺序出现，系统用动画展示对象之间的因果关系。

在 ROS 教学场景中，Publisher、Topic、Subscriber 会依次出现，消息包沿 Topic 通道飞行，Subscriber 收到后发生颜色或状态变化。用户点击 Topic 时，页面弹出相关源码；点击源码后，对应 ROS 节点在图中高亮；点击节点可播放控制动画；拖动机器人时，模拟状态实时更新。

在小车避障场景中，用户能看到小车本体、车头方向、激光雷达扇形扫描、测距射线、障碍物、安全距离阈值、最近命中点、控制器决策和绕行轨迹。用户调整车速、雷达半径、安全距离或障碍密度时，动画结果必须随之改变；拖动障碍物后，扫描、判断和避障动作会重新计算。

如果用户在交互中发现讲解不清楚，可以回到分镜或参数配置重新生成 spec。通过校验后，前端再次渲染，形成“理解资料、生成镜头、交互验证、反馈修正”的循环。
